# Source-only Android native baseline

The official OpenCV 4.12.0 Android AAR's native binaries are unsuitable for this project's source-only baseline: its x86 build configuration enables IPP components. This project builds its own `libopencv_java4.so` from the immutable OpenCV source archive and packages only that library and its matching NDK `libc++_shared.so`. Keep the official 4.12.0 Java wrappers separately and exclude every native binary from the original AAR, including transitive native packaging. Do not resolve duplicate native libraries with `pickFirst`: that can silently restore the prebuilt library.

`tools/build_opencv.ps1` pins the GitHub `4.12.0` source ZIP SHA-256 to `fa3faf7581f1fa943c9e670cf57dd6ba1c5b4178f363a188a2c8bff1eb28b7e4`, Android NDK `28.2.13676358`, and SDK CMake `3.22.1` with its accompanying Ninja. It accepts a local archive and performs no downloads or package installation. It extracts into a separate build directory and verifies every source file against the ZIP on every run; modified or extra source files fail validation. No recursive deletion is used. Python 3 is needed for JNI generation; its exact runtime version is recorded in the audit manifest. The script reproduces source, configuration, toolchain, and dependency selection. It records actual binary hashes and does not claim byte-for-byte identity across differently located or configured hosts.

From the repository root in PowerShell, run:

```powershell
./tools/build_opencv.ps1 `
  -SourceArchive 'C:/path/to/opencv-4.12.0.zip' `
  -AndroidSdk 'C:/path/to/Android/Sdk' `
  -Python 'C:/path/to/python.exe' `
  -BuildRoot 'C:/path/to/work/native-build' `
  -Jobs 4
```

The source archive is available from the [official OpenCV 4.12.0 tag](https://github.com/opencv/opencv/archive/refs/tags/4.12.0.zip). Prepare the pinned NDK/CMake packages in the SDK first. The build targets Android API 26 and the `arm64-v8a` and `x86_64` ABIs. Defaults publish to `scanner-processing-opencv/src/main/jniLibs/<abi>/libopencv_java4.so` and `libc++_shared.so`; `-OutputDirectory` can select a staging directory. Both ABIs are built and audited before publication. Build errors preserve logs and do not publish an unverified ABI. Copy operations can still be interrupted, so release packaging must verify its final contents and hashes.

The module whitelist is `core,imgproc,java`, with `java_bindings_generator` as a required build helper. Core and Imgproc are static archives incorporated into the shared JNI library via `BUILD_FAT_JAVA_LIB=ON` and `BUILD_SHARED_LIBS=OFF`. This includes Android Bitmap conversion JNI, Mat, Core, and Imgproc. Native image codecs are unnecessary: the scanner decodes/encodes through Android Bitmap APIs. The [upstream Bitmap JNI source](https://github.com/opencv/opencv/blob/4.12.0/modules/java/generator/src/cpp/utils.cpp) uses Core, Imgproc, and Android's Bitmap interface; the [JNI build configuration](https://github.com/opencv/opencv/blob/4.12.0/modules/java/jni/CMakeLists.txt) links `jnigraphics`, `log`, `dl`, and `z`.

The script explicitly disables IPP, IPP IW, ITT and tracing, TBB, OpenCL, KleidiCV, Carotene, CPUFeatures, FastCV, CUDA, OpenVINO, Vulkan, Halide, Eigen, LAPACK, Protobuf, Flatbuffers, QR decoding, and codec/video backends. G-API, DNN, Imgcodecs, Highgui, Videoio, tests, examples, documentation, and Kotlin extension builds are excluded. This avoids ADE, downloaded acceleration archives, and media-codec dependencies. The built-in pthread parallel backend remains available. Android's system `libz.so` supplies zlib; the script disables a bundled zlib build and its final ELF dependency checks reject unexpected shared libraries. CMake `ANDROID_PROJECTS_BUILD_TYPE=GRADLE` prepares JNI/Java project metadata, while `BUILD_ANDROID_PROJECTS=OFF` and the explicit `opencv_java` target avoid running an Android Gradle build. No JDK, Ant, or OpenCV Manager is required for the native-only target.

A CMake download hook fails immediately if any optional dependency unexpectedly requests a download. Download-cache metadata stays outside the verified source tree. Python bytecode generation is disabled only during configure/build commands and the previous process setting is restored afterward. After compilation, the static-archive inventory must contain exactly Core and Imgproc; a fallback bundled zlib or other third-party static archive causes failure.

The stock 4.12.0 Java wrapper classes can call this minimized 4.12.0 JNI library for the scanner's Core/Mat/Imgproc/BitmapUtils API. Retaining wrappers for excluded modules does not make those modules available; calling an absent module's native method can raise `UnsatisfiedLinkError`. Keep Java and JNI versions exactly aligned, and rerun scanner instrumentation tests against the final packaged library rather than assuming wrapper compatibility from a version label. Prefer a Java-only vendor dependency whose contents can be independently inspected. The script checks required JNI export prefixes but does not prove every possible wrapper method's compatibility.

Each ABI's audit directory contains exact configure arguments, configure/build logs, ELF headers/program segments/dynamic dependencies, and exported JNI symbols. The script checks the compiled module list, disabled CMake flags, forbidden `cvconfig.h` features, architecture, required scanner JNI exports, and common forbidden binary markers. ELF `LOAD` segment alignment must be at least 16 KB for both OpenCV and the NDK C++ runtime. It uses NDK 28 flexible-page support and explicit 16 KB linker alignment. `audit/native-build-manifest.json` records binary sizes, hashes, tool versions, and dynamic dependencies. These checks establish build provenance and structural invariants; device runtime tests and final APK/AAR inspection are still required.

License material includes OpenCV's [Apache 2.0 license](https://github.com/opencv/opencv/blob/4.12.0/LICENSE), historical source-file notices retained in Core/Imgproc, and the NDK runtime's notices. In particular, `modules/core/src/softfloat.cpp` contains Berkeley SoftFloat BSD-3-Clause and Sun fdlibm permissive notices. Disabling external acceleration does not remove that code or its notice obligations. The script copies OpenCV's license, those SoftFloat/fdlibm notices, and the pinned NDK's `NOTICE` and `NOTICE.toolchain` to `audit/licenses`. This initial set is an audit input, not a blanket claim that every source-file notice has been covered. The project's license collector must include all applicable notices from the compiled source files and distribute the resulting notices with the release. Android system libraries are linked as platform dependencies and are not copied into this distribution.

After building, remove the original native AAR contribution from Gradle resolution, inspect the packaged libraries for both ABIs, and rerun the processing/EXIF/export/integration/benchmark suites on a device or emulator. Confirm `Core.getBuildInformation()` reports only the intended modules and no IPP/ITT/TBB/ADE acceleration. A benchmark run against the official prebuilt AAR does not establish performance or correctness for this source-built baseline.


## Public-build path privacy

The native build applies Clang file-prefix maps for source, build and Android SDK locations. Before compilation it anonymizes tool locations in OpenCV’s generated `version_string.inc` diagnostic include and `opencv_data_config.hpp` sample-data lookup paths (unused by the scanner). The verified upstream source files stay unchanged. Full machine-local configure logs remain in the selected build directory; published metadata redacts paths. Both native binaries are scanned for Windows user-directory paths before publication. This changes build diagnostics and artifact hashes; native behavior is validated again on both supported test emulators.
